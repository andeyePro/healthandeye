# Health&I (healthandeye) — orientation for agents and humans

Personal health, training and diet app: iOS universal + watchOS. Everything is data, nothing is
hard-coded, every module is optional, and the on-disk folder (iCloud Drive by default) is both
the store and the export Claude reads to give advice. Spec: `docs/spec.md`. API contract every
agent codes against: `docs/core-api.md`.

## Layout
- `Sources/HealthAndICore` — pure Swift, Foundation only, Linux-buildable. Model / Store / Rowing / Export / Import / Hints. Tests in `Tests/HealthAndICoreTests` (XCTest).
- `Apps/Shared` — services shared by phone and watch (store controller, BLE, HealthKit, WatchConnectivity). `Apps/iOS`, `Apps/Watch` — SwiftUI apps. Project generated by XcodeGen from `project.yml` (`*.xcodeproj` is gitignored).
- `Martin/` — gitignored, private. Never commit anything from it. The public starter pack describes kit, never a person.

## Build
No Swift toolchain in the container. `scripts/mac-test.sh [build|test|xcode|sh ...]` syncs to the Mac build account and runs there under a lock. Agents: run it FOREGROUND, timeout 600000, never in the background. Martin builds to devices from Xcode on his own login (`xcodegen generate` then open `HealthAndI.xcodeproj`).

## Rules
- Ids are readable slugs. JSON pretty, sorted keys, snake_case, ISO dates. Every field optional except id/name; unknown keys tolerated. The file format is Claude's interface: keep it human.
- The app never edits files Claude wrote (`advice/*.md`); status goes in `advice/status.json`.
- Provenance (`source`) on every measured value. Never silently merge sources.
- TODO.md = open backlog, CHANGELOG.md = done work; both committed with the code they describe.
